# Локальный автономный режим

Цель — играть на одном компьютере без VPS, сайта регистрации и постоянного
интернета. Игровой движок, авторизация и база запускаются локально по команде
и останавливаются после игры. Это локальные серверные процессы, а не перенос
симуляции в клиент. Штатный клиент Forever требует серверного протокола.

**Это инфраструктура для будущего порта Hordes. Сейчас она запускает базовый
Forever из подготовленного образа WoWForEver; режим Hordes в него ещё не перенесён.**
Без настоящего клиента проверена конфигурация и управляющий инструмент,
но не вход в игру, Skyborne или забеги.

## Однократная подготовка с интернетом

Нужны Linux или WSL2 с Docker Engine / Docker Desktop, Compose v2 и Python 3.
Внешний сервер и домен не нужны. Используйте тот же источник, что и прежде:
[Domenklay/WoWForEver](https://github.com/Domenklay/WoWForEver),
проверенный профиль взят из коммита `a7e7747778042b537d062f019bbf2465d67a2863`.
Следуйте его README для подготовки образа `forever-trinitycore:latest`,
сертификатов и извлечения данных из собственного клиента. Не копируйте
клиентские данные или закрытые ключи в Git.

В подготовленном WoWForEver выполняются:

```sh
./scripts/gen-certs.sh
docker compose build worldserver
docker pull mysql:8.0
docker compose run --rm extractor
```

Это этап подготовки с интернетом, он может быть долгим. Он требует настроенного
`.env` по инструкции WoWForEver. Полная локальная установка клиента должна
содержать нужные ресурсы; потоковый клиент может продолжать скачивать их при игре.
Новый локальный профиль создаёт отдельную базу: существующие персонажи из
обычного WoWForEver автоматически в неё не переносятся.

Из корня **hordes-of-azeroth-forever** создайте профиль, указав реальные
абсолютные пути к извлечённым данным и сертификатам:

```sh
python3 tools/offline.py init --data /path/to/WoWForEver/data --certs /path/to/WoWForEver/certs --build 70532
python3 tools/offline.py validate
```

`70532` — ваш экспериментальный клиент; совместимость с ним неполная.
Для документированной сборки укажите `--build 70450`. Значение по умолчанию —
70450. Смена числа не устраняет различия игровых данных и протокола.
`init` проверяет наличие непустых файлов/каталогов, но не их игровую корректность
или подписи сертификатов. Для доверия и запуска клиента используйте процедуру
локального подключения/лаунчера из WoWForEver с адресом `127.0.0.1` и вашим CA.

Пароли базы генерируются автоматически, хранятся в `.offline/` и не попадают
в Git. Повторный `init` откажется перезаписать профиль. Не удаляйте его для
«починки» существующей базы: новый пароль не изменит пароль старого volume.
`--state /absolute/path` позволяет выбрать другое постоянное расположение
профиля; этот параметр ставится **перед** командой во всех вызовах.

## Запуск без загрузок

```sh
python3 tools/offline.py start
python3 tools/offline.py logs
python3 tools/offline.py status
```

Запуск проверяет наличие обоих Docker-образов и игровых файлов. Он не собирает
и не скачивает образы; отсутствующий образ — ошибка. Внутренняя Docker-сеть
не имеет внешнего выхода, наружу опубликованы только порты на `127.0.0.1`.
MySQL не публикуется, сайта и SOAP нет. Из другого компьютера подключиться
нельзя. Не запускайте одновременно обычный Forever: порты 1119/8081/8085 совпадают.

Первый запуск импортирует локальный SQL-дамп из готового образа. Дождитесь
завершения импорта и сообщения готовности worldserver в логах; запущенный
контейнер ещё не означает готовность игры. Не останавливайте процесс во время
первого импорта. Затем один раз создайте учётную запись в локальной консоли:

```sh
python3 tools/offline.py console
```

В консоли worldserver: `bnetaccount create mail@example.com YourUniquePassword`.
Это локальная учётная запись; отправка почты не нужна. Подставьте собственные
данные. Для выхода из присоединённой консоли используйте **Ctrl+P, Ctrl+Q**;
Ctrl+C может остановить сервер. Войдите через подготовленный лаунчер Forever.
Для подтверждения автономности после первичной подготовки отключите интернет,
запустите профиль заново и проверьте вход, бой, сохранение и повторный вход.
Такая игровая проверка в облачной среде пока не выполнена.

После выхода из игры:

```sh
python3 tools/offline.py stop
```

Автозапуска после перезагрузки компьютера нет. Персонажи и прогресс остаются
в отдельном Docker volume `hoa-offline-<идентификатор>-saves`. Команда `stop`
не удаляет контейнеры или volumes. `status` показывает и остановленные процессы.
Идентификатор зависит от абсолютного пути `.offline`; сохраняйте этот путь.

## Сохранения и перенос

Docker volume содержит базу, а **не** папка `.offline`. Сохраните и базу, и
`.offline`, и сертификаты. Перед файловой резервной копией базы остановите
все три контейнера через `stop`; копирование работающей базы может повредить
резервную копию. Удаление Docker volumes / сброс Docker Desktop удаляет прогресс.

Для переноса на машину без интернета заранее сохраните образы:

```sh
docker save -o forever-offline-images.tar forever-trinitycore:latest mysql:8.0
```

На другой машине используйте `docker load -i forever-offline-images.tar`,
перенесите собственные игровые данные и сертификаты. Для переноса существующих
персонажей отдельно восстановите резервную копию базы и исходные пароли.
Не запускайте `init` с новыми паролями поверх перенесённой базы.

## Проверки разработчика

```sh
python3 -m unittest discover -s tools/tests -p 'test_offline.py' -v
```

Тесты проверяют сохранность профиля и паролей, запрет запуска при недостающих
данных/образах, команды без загрузок, сохранение volumes при остановке,
изоляцию сети и разбор настоящим Docker Compose. Они не запускают игровой сервер.
