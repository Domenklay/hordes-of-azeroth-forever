# Установка и запуск через HordesForeverSetup

**Для первого вампирлайка `0.2.0-preview.1` используйте
[новую инструкцию обновления и забега](SURVIVOR.ru.md).**
Пакеты `0.1.0-preview.*`, описанные ниже, были базовым Forever без режима.

Целевая платформа первой версии: **Windows x64**, клиент **1.60.1.70532**,
Docker Desktop в режиме Linux containers. Python отдельно устанавливать не нужно:
он входит в `HordesForeverSetup.exe`.
Окну игрового входа нужен Microsoft WebView2 Runtime (обычно уже установлен
в Windows 11). [Порядок проверок первого комплекта](TESTING.ru.md).

**Это предварительная инфраструктура базового Forever. Сам режим Hordes ещё не
перенесён с VMaNGOS на TrinityCore. Игровой запуск этого комплекта не проверен.**
Совместимость ядра с клиентом 70532 остаётся экспериментальной.

## Что скачать

Готовый установщик появляется в [Releases нашего репозитория](https://github.com/Domenklay/hordes-of-azeroth-forever/releases)
**после успешного завершения** workflow `Offline launcher and engine`.
Файл: `HordesForeverSetup.exe`. Если его нет, исходники ещё не превратились
в готовый выпуск. Не используйте старый HoALauncher: он относится к клиенту 1.12.1.
`0.1.0-preview.2` забракован проверкой первого запуска MySQL: используйте
исправленный `0.1.0-preview.3` или новее после успешного завершения его сборки.

Для локального движка нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/).
Установите его обычным способом с поддержкой WSL2 и запустите Linux engine.
Системные компоненты Docker/WSL не устанавливаются скрытно нашим лаунчером
и не распространяются через наш GitHub.

## Откуда берётся игра

Исходный `ForeverBetaLauncher.exe` версии 1.5.11 получает метаданные из
`http://cdn.nvord.com/nivord/peer/release.json` и `release.sig` (по журналу пользователя).
Это метаданные и подпись, а не готовый архив клиента. Ключ проверки подписи
и формат скачивания здесь не реализованы; наш лаунчер не подменяет официальный
механизм загрузки и не заявляет, что проверил его подпись.

В установщике нажмите **«Скачать клиент через ForeverBetaLauncher.exe…»**,
выберите свой официальный EXE, дождитесь окончания обновления до **1.60.1.70532**
и закройте официальный лаунчер. Затем укажите корень клиента с `Data`,
`.build.info` и `_classic_beta_`. Установщик проверит активный продукт и версию
в `.build.info`; работающая установка должна иметь все нужные локальные ресурсы.
Проверка `.build.info` не подтверждает полноту CASC или целостность всего клиента.

Наши GitHub Releases сейчас **не включают** клиент или извлечённые данные Blizzard.
Опция «Скачать клиент из нашего релиза» предназначена для будущего разрешённого
архива. Пока такого пакета нет, она выдаёт понятную ошибку и не имитирует установку.

## Первоначальная настройка

1. Запустите Docker Desktop и `HordesForeverSetup.exe`.
2. Нажмите **«Установить компоненты из нашего GitHub»**. Будут скачаны готовые
   образы локального движка/MySQL и игровой лаунчер. Каждый блок проверяется
   по размеру и SHA-256. Прерванная установка не активирует неполную версию.
3. Укажите корень полностью обновлённого клиента, затем нажмите
   **«Запустить локальный движок»**. Создадутся ваши собственные сертификаты,
   данные будут извлечены из клиента в отдельную папку, создастся локальная база.
   Первое извлечение и импорт могут занять много времени.
4. Дождитесь готовности worldserver в **«Журнале движка»**. Не прерывайте первый импорт.
5. Откройте **«Создать аккаунт / открыть консоль»**, введите
   `bnetaccount create ваш@email ваш_пароль`. Это локальный аккаунт, письмо не отправляется.
   Для отсоединения: **Ctrl+P, Ctrl+Q**. Ctrl+C может остановить процесс.
6. Нажмите **«Войти в игру»**. Откроется русифицированная версия нашего
   WoWForEver-лаунчера, использующая сертификат этой установки. В первый раз
   нажмите **«Подготовить ПК»**: Windows запросит права для записи hosts и доверия
   к вашему локальному CA. Затем войдите с локальным аккаунтом и нажмите **«Играть»**.

В этой версии установщик и окно игрового входа — два связанных окна.
Основные надписи переведены на русский; часть диагностических сообщений
игрового лаунчера пока отображается на английском. Для языка игры выбран `ruRU`;
нужны соответствующие ресурсы в вашем клиенте.

## Последующие запуски

Откройте установщик, нажмите **«Запустить локальный движок»**, затем **«Войти в игру»**.
Кнопка установки обращается в интернет; обычный запуск использует сохранённый
манифест и локальные файлы. Предварительно установленные Docker-образы не
обновляются и не скачиваются при запуске.

После выхода закройте окно игрового входа и нажмите **«Остановить локальный движок»**.
Закрытие установщика само по себе не останавливает сервер: это защищает
запущенную игру и первый импорт от неожиданного прерывания.
Внешнего хостинга нет; серверные процессы остаются на вашем компьютере.
Подключения разрешены только с `127.0.0.1`.

В `preview.4` добавлены **«Состояние движка»** и **«Скопировать журнал»**.
Если вход недоступен, сначала проверьте состояние: остановленный с ошибкой
процесс требует чтения журнала, а работающий процесс может ещё выполнять импорт.
Кнопка копирования переносит весь текст журнала в буфер обмена. Для обновления
окна лаунчера достаточно закрыть старый EXE и открыть новый: уже извлечённые
данные, настройки и сохранения используются повторно.

В `preview.5` исправлена недоступность всех трёх портов при работающем мире:
вместо `internal` используется bridge-сеть с публикацией только на localhost.
После открытия нового EXE нажмите **«Запустить локальный движок»**. Старая сеть
будет заменена с сохранением базы и данных. Работающий мир сначала проверяется
изнутри контейнера: первичная загрузка или импорт не прерываются ради замены сети.
В «Состоянии движка» отдельно показана доступность портов 1119, 8081 и 8085.

## Где находятся файлы

`%LOCALAPPDATA%\HordesForever`:

- `packages/<версия>` — установленные пакеты и манифест;
- `cache` — проверенные блоки загрузки, повторно используются при установке;
- `certs` — локальные ключи/сертификаты; закрытые ключи не отправляются в Git;
- `data` — извлечённые данные;
- `profile` — параметры и пароли локальной базы;
- `game-settings` — отдельные настройки и сеанс входа игрового лаунчера.

Персонажи находятся **в Docker volume**, а не в перечисленных JSON-файлах.
Не удаляйте volumes, не сбрасывайте Docker Desktop и не перемещайте `profile`.
Резервная копия должна сохранять базу, пароли и сертификаты.
Автоматическая миграция старой базы при смене движка/сборки отключена;
новый пакет не даёт права молча изменять ваши сохранения.

## Сборка и выпуск для разработчика

Workflow: `.github/workflows/offline-launcher.yml`. Запуск через Actions с
уникальной версией либо push тега `offline-v<версия>`.

Он собирает собственный установщик через PyInstaller, адаптирует закреплённый
WoWForEver `a7e7747778042b537d062f019bbf2465d67a2863`, собирает его окно входа,
собирает Docker-образ закреплённого TrinityCore с базой, сохраняет MySQL-образ
и генерирует `offline-manifest.json`. Большие архивы делятся на блоки по 1 ГиБ.
Релиз публикуется только после успешного завершения обеих сборок.
Workflow `offline-patch.yml` позволяет пересобрать установщик с неизменёнными
образами и нативным лаунчером из подтверждённого запуска. Он проверяет запуск
Windows-приложений, серверных бинарников, сертификаты и перезапуск MySQL перед
публикацией, затем публикует полностью загруженный черновик релиза.
Для воспроизведения модификаций игрового лаунчера прилагается его исходный код
`forever-login-source.zip` с оригинальной GPL-2.0 и lockfile.

Временный сертификат сборки содержит только публичную часть, не используется
для реального входа. На машине игрока создаётся отдельный CA; TLS-проверка
остаётся включённой. Исходники и инструкции нельзя считать подтверждением
успешной сборки или входа в мир: проверяйте результаты workflow и настоящий клиент.

Локальные проверки:

```sh
python3 -m unittest discover -s tools/tests -p 'test_*.py' -v
texlua tools/tests/forever.lua
node tools/tests/localization.cjs
```
