# Hordes of Azeroth Forever

Перенос [jonhaldors/hordes-of-azeroth](https://github.com/jonhaldors/hordes-of-azeroth)
в [Domenklay/hordes-of-azeroth-forever](https://github.com/Domenklay/hordes-of-azeroth-forever).
История, GPL-3.0, уведомления об авторах и закреплённые подмодули сохранены.
[Исходная документация](README.upstream.md), [сборка исходной версии](BUILDING.md).

**Статус: исходная база перенесена; полный порт на Forever ещё не реализован.
Играбельной сборки Forever в Releases пока нет.**

## Автономный режим

Для игры без внешнего сервера готовится локальный профиль: игровой движок,
авторизация и сохранения работают на вашем компьютере, запускаются по команде
и не требуют постоянного хостинга. Добавлены запуск/остановка без загрузок,
локальная база, локальная Docker-сеть и подключения только с этого компьютера.
[Подготовка и запуск](config/offline/README.ru.md).
Добавлен [русский установщик для Windows и выпуск пакетов через GitHub](config/offline/LAUNCHER.ru.md),
целевая сборка клиента — 1.60.1.70532. Клиент устанавливается вашим официальным
ForeverBetaLauncher.exe; наши пакеты движка и лаунчера загружаются из GitHub Releases.
Сейчас профиль использует базовый Forever; серверный режим Hordes ещё предстоит
перенести. Полностью убрать серверный процесс из штатного клиента нельзя.

## Целевой клиент

Основание — [наш WoWForEver](https://github.com/Domenklay/WoWForEver).
Он документирует 1.60.1.70450 и экспериментальную пользовательскую 1.60.1.70532.
Нельзя считать эти сборки взаимозаменяемыми. Точная цель и источники закреплены
в [профиле переноса](config/forever.json).

Небесные эльфы — Skyborne: 95 (Альянс) и 96 (Орда) в актуальной ветке Forever
ядра TrinityCore. Это не ночные эльфы и не эльфы крови.

## Что изменено

- Перенесена исходная версия 0.6.3 с её историей и исходниками клиента/сервера.
- Добавлен язык «Русский» в настройках игры и исходного лаунчера: 421 строка
  аддона, 257 строк экрана персонажа и 21 строка лаунчера. Остальное использует
  английский резервный текст. Серверные тексты пока не переведены.
- Экран персонажа исходного Hordes читает допустимые расы и сочетания классов
  из API клиента. Предусмотрено 12 мест, включая дополнительные расы, когда
  клиент их предоставляет. Неизвестные иконки используют знак вопроса.
  Сочетания рас и классов не разблокируются вопреки правилам сервера.
- Обновления исходного лаунчера и сборки направлены в этот форк.

Эти изменения экрана персонажа относятся к исходному клиенту Hordes.
Они сами по себе **не добавляют создание Skyborne в клиент Forever**.
Стандартный экран создания персонажа Forever и серверная проверка рас должны
остаться источником правил для нового порта.

## Проверки

Из корня репозитория:

```sh
lua tools/tests/forever.lua
node tools/tests/localization.cjs
```

В среде с TeX Live вместо `lua` можно использовать `texlua`.
Проверяются чтение рас, ограничения классов, русские имена классов, восстановление
выбора, повторная загрузка, резервный английский текст, подстановки переводов
и адрес обновлений. Это проверки с имитацией API, а не запуск игры.

## Что остаётся для играбельного порта

1. Перенести 76 файлов серверного режима (`server/core/src/game/Bonk`, около
   66 тысяч строк) с VMaNGOS на API TrinityCore Forever: сессии забегов,
   спавны, автобой, способности, прогресс, награды, сохранения и кооператив.
2. Перенести HUD и протокол сообщений аддона на API Forever 16001.
   Простая замена номера Interface в старом TOC не обеспечивает совместимость.
3. Подключить создание Skyborne к реальным данным классов, стартовых зон,
   внешности и навыков выбранной сборки; не заменять race ID 95/96 на старые ID.
4. Завершить русификацию интерфейса и серверных текстов, проверить кириллицу
   и расположение надписей на настоящем клиенте.
5. Собрать и проверить вход, создание обеих рас Skyborne, забег, награды,
   сохранение и повторный вход на собственном клиенте с извлечёнными данными.

Текущий `play.bat`, BUILDING.md и исходный лаунчер запускают версию для
WoW 1.12.1 (5875), а не Forever. Не устанавливайте их в рабочую папку Forever.
Клиент Forever и его игровые данные в этой облачной среде отсутствуют;
проверка игры и создание персонажа в ней не выполнялись.
